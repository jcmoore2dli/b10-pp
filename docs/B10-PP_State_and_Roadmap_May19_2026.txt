SECTION 3 — DO NOT REOPEN THESE DECISIONS
════════════════════════════════════════════════════════════════════════

These are locked. Do not revisit without explicit instruction from J. Moore.

ILR target values: "2" and "3" only. No "2+" anywhere in schema.
Score field ESO: integer 1–4. LEVEL2: integer 1–3. Not ILR levels.
ILR labels in student feedback: Out of scope. Never.
corpusType "CC": It is "COR". Do not reintroduce "CC".
Track on /students: immutable after creation. trackOverrideNote required for override.
PSU as scaffold axis: Not selectable. Always implicit.
MF vocab in scaffold system: Not included. Phase 4 evaluation layer only.
Auto-generated note summary: On-demand only. Never on note write.
EXT as umbrella: EXT is a subtype. One canonized long-form family.
STT Pass 1: Deepgram (disfluency preserved). NOT Whisper. NOT AssemblyAI.
STT Pass 2: AssemblyAI (conditional, instructor-facing only). NOT scoring engine input.
Scoring engine: Claude Sonnet, temperature = 0. Non-negotiable.
Raw transcript: NEVER smoothed before reaching scoring engine.
submissionNumber: Server-side transaction only. Client always writes 0.
Score 1 + Pass 2: Permanently incompatible. Hard block in code.
Auth method: Email/password only.
Entry flow: Access code only on EntryScreen. b10Id from claims — never from user input.
b10Id format: {accessCode}-{sequence} e.g. 26-001-1, 26-001-2
Access code format: YY-NNN (e.g., 26-001, 26-002)
Default enrollment track/baseline: track "B", ilrBaseline "3".
Role authority: Custom claims are the single source of truth for role.
Scoring rubrics: DO NOT MODIFY without Director approval.
Grammar/quality fixes go through post-generation validation layer only.
Passages pipeline reads passageText from Firestore /passages collection.
  passages.json is for frontend display only.
Paraphrase is LEVEL3 (4-point scale), same as ESO.
Model string: claude-sonnet-4-6. Do not revert to deprecated model.
Student identifier: b10Id only. No nicknames or code names for pilot.
Instructor dashboard: roster-first model. Lookup is secondary fallback.
ESO question expansion: Three-phase plan locked.
  Phase 1 (now→pilot): existing bank as-is
  Phase 2 (S1 block): curate best Gemini questions through governance
  Phase 3 (S3): continuously updated bank as selling point
  Technical: add entries to passages.json with task_type: "eso". No pipeline changes needed.
